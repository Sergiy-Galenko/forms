# FormsCraft

Форми та тести українською: імпорт питань з Excel, правильні відповіді, автоматичні бали, публічні посилання й налаштування доступу. Стек: CRA 5, React 19, React Router 6, CSS Modules. Новий Excel-reader завантажується окремим чанком лише під час імпорту.

## Створити тест

1. Відкрийте **Мої форми → Імпортувати Excel**.
2. Завантажте [шаблон](public/templates/test-template.xlsx) та замініть приклади своїми питаннями.
3. Оберіть `.xlsx` (до 2 МБ, до 200 питань, перший аркуш). Перевірте попередній перегляд і назву.
4. Натисніть **Створити тест**, перевірте питання, ключі відповідей та бали в редакторі.
5. Натисніть **Опублікувати**, оберіть обмеження й отримайте посилання.
6. У списку через **Поділитися** можна змінювати обмеження, а через **Статистика → Оновити відповіді** — переглядати відповіді та бали учасників.

Колонки: `Питання`, `Тип`, `Варіанти`, `Правильна відповідь`, `Бали`, `Обов’язкове`. Підтримуються також англійські заголовки. Варіанти розділяйте `|`; правильну відповідь задавайте текстом або номером варіанта (від 1), кілька номерів — через кому, наприклад `1,3`. Для числових варіантів у колонці правильної відповіді використовуйте саме їхні номери. Порожні рядки пропускаються; помилки показуються з номером рядка. Старий `.xls` потрібно зберегти як `.xlsx`.

Типи: `text`, `textarea`, `single`, `multiple`, `scale`, `email`, `number`, `date`. Якщо тип не вказано, імпорт визначає текст / один / кілька за варіантами та ключем. Для шкали імпорт використовує 1–5, межі можна змінити в редакторі. Для автоматичного оцінювання імпортоване питання має мати правильну відповідь і додатні бали.

Кілька відповідей оцінюються за точним повним набором, без часткових балів. Для тексту регістр і пробіли на краях ігноруються; альтернативи можна розділити `|`. Числа порівнюються чисельно. Вільний текст оцінюється збігом, без AI-перевірки змісту. У редакторі можна залишити питання без оцінювання.

## Локальний запуск повного сценарію

```sh
npm install
npm run build
npm run serve:local
```

Відкрийте `http://127.0.0.1:4177`. Цей сервер обслуговує production-збірку та API; дані зберігає у `.local-data/`, яка виключена з Git. Це **однопроцесний режим розробки**, не хмарне сховище. Локальні посилання доступні лише там, де доступний цей сервер. Після змін фронтенду повторіть build, після змін API перезапустіть сервер.

`npm start` запускає лише CRA-фронтенд. Для тестування публікації використовуйте повний сценарій вище або `vercel dev` із налаштованим сховищем.

```sh
CI=true npm test -- --watchAll=false
npm run test:api
npx eslint src --ext .js --max-warnings=0
```

## Публічний сайт на Vercel

Для посилань, які відкриваються на інших пристроях, потрібні API та спільне сховище:

1. Підключіть **Upstash Redis** до Vercel-проєкту через Marketplace.
2. Додайте серверні змінні `UPSTASH_REDIS_REST_URL` і `UPSTASH_REDIS_REST_TOKEN` до відповідних середовищ. Зразок — [.env.example](.env.example).
3. Розгорніть цю версію. `api/tests.js` працює як Vercel Function; `vercel.json` зберігає API та маршрути SPA.
4. Перевірте публікацію й проходження у двох окремих браузерних сесіях.

Не додавайте префікс `REACT_APP_` до секретів сховища. У production файловий режим вимкнено; без Redis API повертає зрозумілу помилку 503 і не видає удаваного публічного посилання.

Віддалене сховище й production-деплой у поточній сесії **не налаштовано**: підключення Vercel повернуло 403, потрібне підтвердження доступу до команди. Повний сценарій перевірено локально з окремими браузерами та серверним файловим сховищем. Деталі — у [звіті](docs/excel-tests.md).

## Обмеження доступу та дані

- Увімкнення/вимкнення публічного доступу.
- Пароль, який перевіряє сервер; на сервері зберігається scrypt-хеш.
- Точний дедлайн доступу; інтерфейс показує місцевий час, сервер використовує ISO UTC.
- Загальна кількість відповідей до 5000. Ліміт перевіряється атомарно під час відправлення.
- Одна відповідь у браузері через HttpOnly-cookie. Інший браузер або очищення cookie дозволяє нову спробу; це не ідентифікація людини.
- Показ або приховування особистого результату учасника.

Правильні відповіді, паролі, чужі відповіді та ключ керування не повертаються публічним API. Оцінку обчислює сервер, надіслані клієнтом бали не використовуються. Зміна опублікованого тесту скасовує старі сеанси проходження. Повторний запит відправлення з тим самим attempt-id не створює дубля.

Чернетки та секретні ключі керування зберігаються локально в автора в наявному `forms` localStorage. Опубліковані тести та відповіді зберігаються на сервері. **Не очищуйте дані браузера автора:** без ключа керування відновлення доступу з іншого пристрою не передбачене. Не передавайте іншим повний вміст localStorage. Сам публічний URL не містить ключа керування.

Старі `/form/:id` лишаються локальним переглядом. Нові спільні посилання мають вигляд `/form/pub_<uuid>`. Усі інші маршрути збережено. IPify більше не використовується.

## Структура та дизайн

- `src/components/ExcelImport/` — вибір файлу та попередній перегляд.
- `src/utils/excelImport.js` — чиста перевірка рядків, читання `.xlsx` через lazy import.
- `src/components/FormBuilder/AnswerKey.js` — правильні відповіді та бали.
- `src/components/ShareModal/` — публікація та обмеження.
- `src/pages/PublicTestPage.js` — проходження спільного тесту та результат.
- `src/services/TestsApi.js` — клієнт API.
- `server/` — валідація, оцінювання, доступ, сеанси та сховище.
- `api/tests.js` — точка входу Vercel Function.
- `src/context/FormsContext.js` — локальні чернетки й керування публікаціями.
- `src/components/ui/`, `src/layouts/`, `src/styles/` — доступні UI-компоненти, layout, токени й CSS Modules.

Токени — `src/styles/tokens.css`; глобальні лише reset, типографіка та фокус у `base.css`. Новий UI-компонент додавайте власною папкою з `.js` і `.module.css`, використовуйте токени й нативну семантику, додавайте тести змістовної поведінки. Тема системна або явна з ключем `formscraft:appearance:v1`, застосовується до React інлайн-скриптом.

Історичні результати редизайну збережено в [docs/verification.md](docs/verification.md); вони стосуються попередньої ревізії, а не вимірів після додавання Excel/API.
